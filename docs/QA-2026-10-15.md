# INKRUSH QA — 15 October 2026

Scope: discovery and search, title/chapters, page delivery, public search pages, privacy controls, and legacy reader analytics.

## Findings fixed

1. **Unknown collection/guide URLs returned HTTP 200.** Live requests to `/browse/not-a-category` and `/guides/not-a-guide` returned 200 while rendering a not-found result. Extended pre-stream route validation now returns 404 and `X-Robots-Tag: noindex`, including invalid nested paths. Valid guides, privacy and robots still return 200.
2. **Chapter filtering carried into the next comic.** React reused the same Detail instance between title routes; its chapter-query state was only initialized at mount. Keyed the Detail instance by title ID and selected language so unrelated titles cannot retain the previous filter or sort state. This fix is established by component lifecycle/code inspection; interactive browser reproduction was unavailable.
3. **Initial Arrow Up skipped the last prediction.** With current index -1 and six suggestions, the old expression produced 4 instead of 5. A shared keyboard helper now correctly handles the first Up/Down, wraparound, empty lists and a suggestion list shrinking while selected.
4. **Opt-out in another browser tab did not revoke analytics here.** The integration only read consent on mount and listened for local privacy-dialog actions. A storage-event subscription now propagates changes and storage clearing; the analytics effect cleans up listeners and disables future events when consent is revoked. Regression coverage dispatches actual storage-shaped events through EventTarget, checks unrelated settings are ignored, and verifies cleanup.
5. **Legacy `/reader` links had incorrect analytics labels.** The sanitized route mapper now treats `/reader` and `/reader.html` like the root reader. Unknown/prototype-property fragment names fall back to Discover instead of being treated as valid screen names.
